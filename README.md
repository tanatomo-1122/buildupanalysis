# ビルドアップ評価戦術ボード

2Dピッチ上に22人＋ボールを自由に配置し、特定の局面における
**期待前進値（構造的な優位性）** をリアルタイムに算出・可視化する仮説検証ツール。

チームスタイル・選手特性は eFootball の定義に準拠している。

## セットアップ

```bash
npm install
npm run dev      # http://localhost:5173
```

```bash
npm run build    # 型チェック + 本番ビルド (dist/)
npm run preview  # ビルド結果の確認
```

Vercel にそのままデプロイ可（フレームワークプリセット: Vite）。

## 使い方

- **ドラッグ**：ピッチ上の選手アイコンとボールを自由に動かす
- **クリック**：選手を選択 → 右パネルでポジション・攻撃時特性・守備時特性・座標を編集
- **ボール保持（攻撃／守備）**：どちらのチームがボールを持っているかを切り替える
- **局面（シーン）**：チームスタイルのどの列を適用するかを切り替える
- **フォーメーション**：自チーム／相手それぞれに設定。ライン高さで全体を押し上げ／押し下げ
- **評価の起点**：GK 以外の全員がボールを持った場合の平均を取るか、現在のボール位置1点で見るか
- **パス距離の重み**：μ（最適パス距離）と σ（許容幅）で、どの距離のパスを高く評価するか調整
- **フォーメーション比較**：自チームの全17形を総当たりで評価し、攻撃／守備それぞれの順位を一覧
- **上部のプリセット**：典型的な4局面をワンクリックで呼び出し
- 配置とパラメータはブラウザに自動保存。JSONで書き出し／読み込みも可能

黄色いリングの選手がボールホルダー（ボールに最も近い保持側の選手）で、総和からは除外されます。

### 攻撃時／守備時の切り替え

「ボール保持」を切り替えると攻守が入れ替わります。

| | 保持側 | 非保持側 |
| --- | --- | --- |
| 発動する選手特性 | 攻撃時特性 | 守備時特性 |
| チームスタイルの列 | 攻撃時（または奪った時） | 守備時（または奪われた時） |

期待前進値は**保持側の攻撃方向**で算出されます。「自チームが守備」にすると
スコアは「相手にどれだけ前進を許すか」を表す指標になり、自分の守備ブロックの
検証に使えます。ボールが保持側の選手から離れているときは警告が出て、
ワンクリックで最寄りの保持側選手へボールを寄せられます。

### 評価の起点（起点平均）

既定では、保持側の **GK 以外の各選手を順にボールホルダーに置いて**期待前進値を計算し、
その平均をメインスコアにしています。

```
期待前進値(平均) = (1/N) Σ_h [ Σ_i w_i × PC_i × ΔX_i ]     ボールを選手 h の足元に置いたとき
```

ボールを1点に置いた評価は「そこに置いたから」の影響が強く出ます。GK 以外の全員を
順に起点にして平均すると、ボールの置き場所に左右されない「その配置そのものの
前進しやすさ」になり、フォーメーション比較の公平性も上がります。

- 各サブ評価では起点の選手自身を総和から除外するので、「自分を除く10人への前進の期待値」を
  N 通り平均していることになる
- **ピッチの矢印・支配領域は現在のボール位置のまま**描かれる（起点ごとに変わるため）。
  スコア直下の内訳表も現在のボール位置1点の中身なので、上のスコアとは一致しない
- 「起点別の内訳」パネルで、どの選手が持ったときに前進できるか／詰まるかを一覧できる。
  「盤面で見る」を押すとボールがその選手に移り、ピッチがその起点の状態になる
- 「現在のボール位置だけ」に切り替えれば、特定の局面を作り込んだ従来の評価に戻せる

### フォーメーション比較

盤面の下にある比較表は、**チームスタイル・選手特性・相手チーム（フォーメーションとスタイル）を
固定したまま**、自チームのフォーメーションだけを17通り総当たりで入れ替えた結果を並べます。

| 指標 | 意味 | 良し悪し |
| --- | --- | --- |
| 自チームの前進 | 自チームがボールを持ったときの期待前進値 | 大きいほど良い |
| 相手に許した前進 | 相手がボールを持ったときの相手の期待前進値 | 小さいほど守備が固い |

- 特性は背番号で引き継がれるため、比較のあいだ一切変化しない
- **起点平均モード（既定）では、どちらのカラムもボール位置に一切依存しない**
  （17形 × 攻守 × 起点10 = 340 評価を毎回回している。1回あたり 20ms 程度）
- 単一起点モードのときだけ、攻撃側は**現在のボール位置**、守備側は**相手の最寄り選手の足元**を使う。
  相手チームは固定なので、守備側の起点は全フォーメーションで共通になり比較が公平になる
- 表の棒は「最下位との差」を描いているので、どちらのカラムも長いほど良い選択と読める
- 「適用」ボタンでその形を盤面に反映できる（特性はそのまま）

## 座標系

ピッチ左下を原点とする実寸メートル系。

- `x`: 0（自陣ゴールライン）〜 105（相手ゴールライン）— 自チームの攻撃方向は **+X**
- `y`: 0（下タッチライン）〜 68（上タッチライン）

相手チームは常に自チームの鏡像 `(105 - x, 68 - y)` として扱うため、
フォーメーションを1つ定義すれば左右の利き（RSB が相手から見て右に来ること）も自動的に正しくなる。

## 計算モデル

### 1. 暫定到達領域（ベクトルの自動算出）

矢印を個別に引くのではなく、特性変数の掛け合わせで自動生成する。

```
暫定到達領域 = 基本座標 + チームスタイル係数 + 選手特性係数
```

係数は次の5基底の合成として定義される（`src/types.ts` の `VectorCoeff`）。

| 基底 | 意味 |
| --- | --- |
| `forward` | 攻撃方向（自チームが攻める向き）への距離 [m] |
| `width` | ピッチ中央線 y=34 から外側（タッチライン方向）への距離 [m]。負値で内側に絞る |
| `ballward` | ボールへ向かう単位ベクトル方向への距離 [m]。負値でボールから離れる |
| `goalward` | 自陣ゴール方向（撤退）への距離 [m] |
| `goalmouth` | 相手ゴール中央 (105, 34) へ向かう単位ベクトル方向への距離 [m] |

チームスタイル・選手特性それぞれに強度スライダー（0〜2倍）があり、
「スタイルだけの影響」「特性だけの影響」を切り分けて見られる。結果はピッチ内にクランプされる。

### 2. フォーメーション（`src/data/formations.ts`）

17種類。自チーム基準の座標で定義し、相手側は鏡映して使う。

```
4-3-3 / 4-1-2-3 / 4-1-3-2 / 4-1-4-1 / 3-4-3 / 3-2-3-2 / 3-2-2-3 / 3-3-1-3 / 3-1-2-4
2-2-4-2 / 4-2-1-3 / 4-2-3-1 / 4-4-2 / 4-2-2-2 / 3-2-4-1 / 3-4-2-1 / 5-3-2
```

`rearrangeToFormation()` が背番号で対応付けて座標とポジション表記だけを差し替えるため、
フォーメーションを変えても特性は失われない。

### 3. チームスタイル（`src/data/styles.ts`）

6種類。それぞれ **攻撃時 / 守備時 / ボールを奪った時 / ボールを奪われた時** の
4局面ぶんの係数と説明文を持つ。

| スタイル | 攻撃時の性格 |
| --- | --- |
| ポゼッション | ボールに近づく動き |
| ショートカウンター | 積極的に前へ飛び出し、縦に速い |
| ロングカウンター | 選手間の距離を長く保ち、遠い味方も裏へ |
| サイドアタック | サイドから攻めてクロス、複数人がゴール前へ |
| ロングボール | 中盤を省略、セカンドボールを拾うサポート |
| オーバーロード | ボール周辺に人を集めて狭い局面で数的優位 |

**局面（シーン）セレクタ**がどの列を適用するかを決める。

| シーン | 保持側 | 非保持側 |
| --- | --- | --- |
| 保持（ビルドアップ） | 攻撃時 | 守備時 |
| トランジション（奪った直後） | ボールを奪った時 | ボールを奪われた時 |

### 4. 選手特性（`src/data/skills.ts`）

**ポジションごとに選択肢が変わり、攻撃時と守備時で別の特性を持つ。**
1人の選手が攻撃時特性と守備時特性の両方を保持し、ボール保持の別で発動する側が決まる。

- ボールを保持している側は **攻撃時特性** が発動
- 非保持側は **守備時特性** が発動

ポジションは `GK / CB / RSB / LSB / DMF / CMF / RMF / LMF / OMF / RWG / LWG / ST / CF`。
特性は攻撃20種・守備13種（計33種）。

**特性は勝手に書き換えられない。** ポジションを変えても、フォーメーションを
変えても、設定した特性はそのまま維持される。新しいポジションでは本来選べない
特性になった場合はプルダウンに残したうえで「◯◯ 本来の選択肢外」と印を付ける。
既定値に戻したいときはフォーメーション欄の「特性をポジション既定に戻す」を使う。

### 5. Pitch Control（空間支配率）

複雑なパスカット判定は含めず、距離ベースで簡略化している。

```
w = exp(-d / λ)                            影響力（d は対象地点までの距離）
PC(p) = Σ_保持側 w / (Σ_保持側 w + Σ_守備側 w)     0.0 〜 1.0
```

- **λ（減衰率）**：大きいほど遠くの選手も効く。小さいほど「その場にいる選手だけ」が効く
- **算出方式**
  - `チーム合算`：保持側全員の影響を合算。周囲のサポートの価値が反映される
  - `個人 vs 守備側全員`：本人の影響力のみ。「1人で受け切れるか」を見る
- **守備側も到達領域で評価**：OFF にすると守備側は現在地のまま評価。プレス前後の比較に使う

ヒートマップの色は保持の別と関係なく、常に自チーム＝シアン／相手＝ローズで描いている。

### 6. パス距離の重み（`src/logic/passWeight.ts`）

```
w_i = exp( -(d_i - μ)² / 2σ² )
```

- `d_i`：ボール現在地から選手 i の到達地点までの**直線距離**＝そのパスの飛距離。
  前進量 `ΔX_i` とは別の量（`ΔX` は攻撃方向への射影、`d` は距離そのもの）
- `μ`：最も価値を置くパス距離 [m]。ここで w = 1.0
- `σ`：許容幅 [m]。大きいほど距離にこだわらず、σ → ∞ で重みなしに漸近する

足元3mのパスと60mのロングボールを ΔX の大きさだけで評価してしまう問題を補正するための項。
`w` は常に (0, 1] なので、掛けてもスコアの符号は変わらない。
トグルを OFF にすると `w = 1` となり、従来の式に戻せる（A/B 比較用）。

調整パネルには重み曲線が表示され、いま盤面にいる各選手のパス距離が曲線上のどこに
乗っているかを点で確認できる。

### 7. 目的関数（期待前進値）

1つの起点（ボール位置）に対する値：

```
V(ball) = Σ ( w_i × PC_i × ΔX_i )   対象：保持側のうちボールホルダーを除く10人
```

- `w_i`：パス距離のガウス重み（上記。無効時は 1）
- `PC_i`：選手 i の暫定到達領域における空間支配率
- `ΔX_i`：ボール現在地から到達地点への距離を**保持側の攻撃方向**に射影した値。マイナスも許容
  - 「ΔX のマイナスを切り捨て」を ON にすると下がる動きの負の寄与を 0 にできる

そのうえで、既定では起点を振って平均する（`src/logic/holderAverage.ts`）：

```
期待前進値 = (1/N) Σ_h V(h.pos)      h = 保持側の GK 以外（通常 N = 10）
```

スコアは絶対値に意味があるわけではなく、**同じパラメータ設定のもとで局面同士を比較する**ための指標。
重みの ON/OFF、μ、起点モードを変えるとスケール自体が変わるので、比較は同じ設定のなかで行うこと。

## 構成

```
src/
├── types.ts                 ドメイン型定義
├── constants.ts             ピッチ寸法 / 既定パラメータ
├── presets.ts               局面プリセット
├── data/
│   ├── skills.ts            選手特性（ポジション別・攻守別）
│   ├── styles.ts            チームスタイル（6種 × 4局面）
│   └── formations.ts        フォーメーション（17種）と配置の展開
├── logic/
│   ├── vectors.ts           ベクトル合成・暫定到達領域の算出
│   ├── pitchControl.ts      距離ベースの簡略 Pitch Control
│   ├── passWeight.ts        パス距離のガウス重み
│   ├── evaluate.ts          期待前進値の算出（目的関数）
│   ├── holderAverage.ts     GK以外の各起点で評価して平均を取る
│   └── compare.ts           フォーメーション総当たり比較
├── components/
│   ├── Pitch.tsx            SVG ピッチ描画 + ドラッグ&ドロップ
│   ├── Heatmap.tsx          Canvas による PC 場の描画
│   ├── ControlPanel.tsx     パラメータ調整パネル
│   ├── ScorePanel.tsx       スコア内訳
│   ├── FormationCompare.tsx フォーメーション比較表
│   ├── PassWeightCurve.tsx  パス距離の重み曲線
│   ├── HolderBreakdown.tsx  起点別の内訳
│   └── ui.tsx               小さな UI 部品
└── App.tsx                  状態管理と全体レイアウト
```

状態は `App.tsx` の `BoardState`（選手配列・ボール座標・パラメータ・フォーメーション）に
一元化されており、評価結果は `useMemo` で導出される派生値。

## 拡張のヒント

- **特性の効きを変える**：`src/data/skills.ts` の `coeff` を書き換える。それがそのまま仮説のチューニング
- **特性を増やす**：同じ配列に1要素足すだけ。`positions` に列挙したポジションのプルダウンに出る
- **スタイルを増やす**：`src/data/styles.ts` に4局面ぶんの係数を持つ要素を追加
- **フォーメーションを増やす**：`src/data/formations.ts` に自チーム基準の座標を定義（相手側は自動で鏡映）。
  適用は `rearrangeToFormation()` が背番号で対応付けて座標とポジションだけを差し替える
- **PC の式を変える**：`src/logic/pitchControl.ts` の `influence()` を差し替える
  （速度・向きを考慮した楕円モデルなどに拡張しやすい）
- **目的関数を変える**：`src/logic/evaluate.ts`。ΔX の代わりにゾーン価値の重みを掛けるなど
- **距離の重みを変える**：`src/logic/passWeight.ts`。ガウス以外（対数正規など）に差し替えやすい
- **起点の選び方を変える**：`src/logic/holderAverage.ts` の `outfieldHolders()`。
  重み付き平均にしたり、後方の選手だけに絞ったりできる
- **注意**：`Heatmap.tsx` は速度のため PC 式を手書きで展開している。
  `pitchControl.ts` を変更したらこちらも合わせること
