# eFootball 戦術提案ボード

登録した選手と指定したチームスタイルから、**相手のフォーメーションに最も噛み合う自分の
フォーメーションとスタメン11人**を提案するツール。
提案結果は 2D の戦術ボードで確認・微調整できます。

評価モデル（チームスタイル・プレースタイル・空間支配率・パスコース）は eFootball の
定義に準拠しており、定数はコード側で固定しています。

## セットアップ

### 1. Supabase を用意する

ユーザー登録と選手データの保存に Supabase を使います。

1. [Supabase](https://supabase.com) でプロジェクトを作成
2. SQL Editor で `supabase/schema.sql` を実行（`profiles` と `squad_players` が作られます）
3. Project Settings → API から URL と anon キーを取得

### 2. 環境変数

```bash
cp .env.example .env.local
# .env.local を編集
#   NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
#   NEXT_PUBLIC_SUPABASE_ANON_KEY=ey...
```

### 3. 起動

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 型チェック + 本番ビルド (dist/)
```

Vercel にそのままデプロイできます（フレームワークプリセット: Vite）。
その場合は同じ2つの環境変数を Vercel の Environment Variables に設定してください。

> **Supabase を用意する前に触ってみたい場合**
> `node tools/mock-supabase.mjs` で PostgREST 互換のインメモリのモックが
> `http://localhost:54321` に立ちます。`.env.local` にその URL と適当なキーを書けば
> 画面を通しで確認できます（プロセスを止めるとデータは消えます。開発用です）。

## 画面

| タブ | できること |
| --- | --- |
| ユーザー | eFootball のユーザーネームと ID で登録・切り替え |
| 選手登録 | 23名の選手名・メインポジション・攻守のプレースタイルを登録 |
| 戦術提案 | 相手の布陣とスタイルを指定して、最適なフォーメーションとスタメンを提案 |
| 戦術ボード | 提案された布陣をドラッグで動かして検証 |

選手名が入っている選手だけが起用対象になります（提案には11名以上が必要）。

## 戦術提案のしくみ

17 フォーメーションそれぞれについて、次の手順でスコアを出してランキングします。

### 1. 最適な11人の割り当て（`src/logic/assign.ts`）

各スロットに誰を置くのが良いかを **ハンガリアン法** で解きます。貪欲だと
「一番良い選手を先に取られた枠が総崩れになる」ため、全体最適を解いています。

適性スコアは次の合計です（`src/data/positions.ts`）。

- **ポジション適性** 0〜100（本職100／適性あり70〜／兼任可50〜／専門外）
- **プレースタイルの噛み合い** 攻撃時が本来そのポジションで選べるものなら +12、守備時なら +8

### 2. 盤面評価と局所探索（`src/logic/recommend.ts`）

適性だけで組んだ11人を実際に盤面評価し、ベンチとの入れ替えで改善できるかを
山登り法で探します（1スロットあたり上位3名、最大2ラウンド）。

目的関数には **本職から外れた起用への減点** を入れています。

```
目的関数 = 戦術スコア − Σ 8 × (100 − ポジション適性) / 100
```

盤面評価は「その位置でどう振る舞うか」しか見ないため、これが無いと
「本職CBがベンチにいるのにサイドバックをCBに置く」ような布陣に流れます。
「兼任可（適性62）」を1枚入れると約3.0点の減点になり、それを上回る
戦術的な利得がなければ採用されません。

### 3. ランキング

| 指標 | 意味 | 良し悪し |
| --- | --- | --- |
| 自チームの前進 | 自チームがボールを持ったときの期待前進値 | 大きいほど良い |
| 相手に許す前進 | 相手がボールを持ったときの相手の期待前進値 | 小さいほど良い |
| バランス | 自チームの前進 − 相手に許す前進 | 大きいほど良い |

「何を基準に選ぶか」で攻撃重視／守備重視／バランスを切り替えられます。

## 評価モデル

期待前進値は、保持側の GK 以外の各選手を順にボールホルダーに置いて計算し、その平均を取ります。

```
V(ball) = Σ ( w_i × PC_i × ΔX_i )     保持側のうちボールホルダーを除く10人
期待前進値 = (1/N) Σ_h V(h.pos)        h = 保持側の GK 以外（N = 10）
```

起点平均にしているので、ボールをどこに置いたかに依存しません。

### 座標系

ピッチ左下を原点とする実寸メートル系。x: 0（自陣ゴール）〜105（相手ゴール）、y: 0〜68。
自チームの攻撃方向は +X。相手チームは常に鏡像 `(105 - x, 68 - y)` として扱うので、
フォーメーションを1つ定義すれば左右の利きも自動的に正しくなります。

### 暫定到達領域

```
暫定到達領域 = 基本座標 + チームスタイル係数 + プレースタイル係数
```

係数は5基底（`forward` 攻撃方向 / `width` 外側 / `ballward` ボール方向 /
`goalward` 自陣方向 / `goalmouth` 相手ゴール中央）の合成です（`src/types.ts` の `VectorCoeff`）。

### チームスタイル（`src/data/styles.ts`）

ポゼッション / ショートカウンター / ロングカウンター / サイドアタック / ロングボール / オーバーロード。
それぞれ **攻撃時 / 守備時 / ボールを奪った時 / ボールを奪われた時** の4局面ぶんの係数を持ち、
「局面」セレクタとボール保持の別で適用される列が決まります。

| 局面 | 保持側 | 非保持側 |
| --- | --- | --- |
| 保持（ビルドアップ） | 攻撃時 | 守備時 |
| トランジション（奪った直後） | ボールを奪った時 | ボールを奪われた時 |

### プレースタイル（`src/data/skills.ts`）

ポジションごとに選択肢が変わり、1人が攻撃時と守備時の両方を持ちます。
保持側は攻撃時、非保持側は守備時が発動します。攻撃20種・守備13種（計33種）。

### Pitch Control（`src/logic/pitchControl.ts`）

```
w = exp(-d / λ)                                     λ = 8m
PC(p) = Σ保持側 w / (Σ保持側 w + Σ守備側 w)          0.0 〜 1.0
```

### パスコース評価（`src/logic/passLane.ts`）

到達地点だけでなく、ボール → 到達地点の線分をサンプリングして
**最も低い PC（ボトルネック）** をそのパスの成功確率にします。

```
PC(x) = Σ保持側 w / ( Σ保持側 w + Σ守備側 w × I(x, L) )
I     = 1 - loft(L) × (1 - (4(x/L - 0.5)²)^p)
```

`I` はインターセプト可能性。`loft(L)` はパス距離から決まる浮き具合で、
12m 以下は 0（グラウンダー、コース上の敵を全員数える）、35m 以上は 1
（フライ、中間地点の敵を頭上越えで無視）。キック直後と落下地点は距離によらず `I = 1` なので、
蹴り出しを塞がれている／落下点に敵がいる場合はきちんと減点されます。`p = 2`。

### パス距離の重み（`src/logic/passWeight.ts`）

```
w_i = exp( -(d_i - μ)² / 2σ² )       μ = 18m, σ = 12m
```

`d_i` はボールから到達地点までの直線距離（パスの飛距離）。
足元すぎるパスと無理な超ロングパスを同時に減点します。

## チューニングの入り口

UI から触れるのは戦術上の選択だけで、モデルの定数はコードにあります。

- **プレースタイルの効き** … `src/data/skills.ts` の `coeff`
- **チームスタイルの効き** … `src/data/styles.ts` の各局面の `coeff`
- **フォーメーション** … `src/data/formations.ts`（自チーム基準の座標。相手側は自動で鏡映）
- **ポジション適性** … `src/data/positions.ts` の `FIT`
- **本職から外れた起用への減点** … `src/logic/recommend.ts` の `FIT_PENALTY`
- **探索の強さ** … 同じく `SEARCH`（候補数・ラウンド数・起点サンプル数）
- **モデル定数（λ・μ・σ・弾道の閾値）** … `src/constants.ts` の `DEFAULT_PARAMS`
- **注意** … `Heatmap.tsx` は速度のため PC 式を手書きで展開しています。
  `pitchControl.ts` を変更したらこちらも合わせてください
